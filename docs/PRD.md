# PRD: ИИ-бот продаж Yonda в Instagram Direct (MVP)

Статус: **v0.3 — утверждён заказчиком 2026-10-08** · 2026-10-08
Владелец: Шухрат · Исполнение: n8n + Claude

---

## 1. Проблема

Лиды из таргета (Click-to-Direct) приходят в Direct, но обрабатываются вручную. Это даёт медленные ответы, потерю лидов вне рабочего времени и нулевую видимость воронки: какие кампании приводят к оплатам, а какие нет.

## 2. Цель MVP

Бот от имени магазина ведёт горячего лида из рекламы от первого сообщения до получения скриншота оплаты. Он фиксирует каждый шаг в Google-таблице и передаёт диалог менеджеру через Telegram, когда это необходимо.

## 3. Критерии успеха (проверяем через 2 недели на живом трафике)

| # | Критерий | Порог |
|---|---|---|
| 1 | Время первого ответа | < 1 мин в 95% случаев |
| 2 | Лиды, по которым бот правильно определил товар из рекламы | ≥ 90% |
| 3 | Каждый лид есть в воронке с актуальным статусом | 100% |
| 4 | Уведомление в TG при заявке или эскалации | 100%, задержка < 1 мин |
| 5 | Бот не отвечает после вмешательства менеджера | 0 нарушений |
| 6 | Бот не выдумывает цены и товары, которых нет в таблице | 0 случаев на выборке 30 диалогов |
| 7 | Конверсия «лид → скриншот оплаты» | замеряется в пилоте и становится базой для следующих итераций (ручной базы нет) |
| 8 | Расходы на инфраструктуру и ИИ | ≤ ~$15/мес |

## 4. Объём

### Входит в MVP
- Приём сообщений из Instagram Direct (текст, изображения, нажатия постоянного меню).
- **Определение товара из рекламы**, 3 уровня: `referral.ad_id` → уникальный стартовый текст объявления → уточняющий вопрос.
- Диалог продажи по скриптам и карточкам товаров из Google Sheets.
- Сбор заявки: товар/кол-во → сумма → ссылки Click/Payme → телефон, время получения, адрес → скриншот оплаты.
- Воронка в Google Sheets: статусы, кампания, товар, данные заказа.
- Передача менеджеру: (а) пункт постоянного меню «Связаться с менеджером», (б) просьба текстом, (в) голосовое сообщение, (г) вопрос вне скрипта или товара, (д) получен скриншот оплаты.
- Уведомление в Telegram: имя/ник, ссылка на чат, кампания, товар, суть, что нужно сделать, скриншот (если есть).
- Автоматическая пауза бота, если менеджер ответил сам (по echo-сообщениям).
- Склейка подряд идущих сообщений (буфер ~15 с).
- Языки: русский (основной), узбекский (отвечает на языке клиента).

### Не входит в MVP
- Остатки товаров.
- Расшифровка голосовых (голосовое → сразу менеджеру).
- Проверка оплаты (только менеджер; бот не подтверждает оплату).
- Дожимы вне окна 24 ч и тег HUMAN_AGENT (требует App Review).
- Автоимпорт кампаний из Marketing API (справочник ad_id ведётся вручную).
- Интеграция с Bitrix24 или другой CRM.
- Ответы на комментарии под постами.
- Детальная проработка tone of voice и скриптов (отдельная итерация).

## 5. Ограничения

- **Бюджет:** VPS ≈ $5–10/мес + Claude Haiku 5.5 ≈ $3–6/мес при 10–20 лидах в день. Платных подписок (ManyChat, n8n Cloud) нет.
- **Meta:** работаем на Standard Access для своего аккаунта, без App Review. Окно ответа 24 ч. Токен живёт 60 дней (автопродление).
- **n8n:** разработка на демо (14 дней), прод на VPS. **Реклама на демо не запускается.**
- **Хранилища:** Google Sheets (воронка, скрипты, товары, справочник рекламы) + Supabase free (история диалогов, состояние, флаг паузы). Supabase переносить при переезде на VPS не нужно.
- **Google Sheets API:** лимит ~60 запросов/мин, поэтому скрипты и товары кешируются, а не читаются на каждое сообщение.

## 6. Архитектура

```
Instagram (Click-to-Direct)
   │ webhook: messages, messaging_postbacks, messaging_referral
   ▼
n8n ─ WF1 «Приём»
   ├─ проверка подписи, защита от дублей по mid
   ├─ echo от менеджера? → пауза лида, выход
   ├─ referral? → сохранить ad_id в лид
   ├─ голосовое / меню «менеджер»? → WF3
   └─ запись в Supabase.inbox → Wait 15с → «я последний?» → WF2
n8n ─ WF2 «Диалог»
   ├─ загрузка лида + истории (Supabase), справочников (кеш Sheets)
   ├─ Claude Haiku 5.5 + инструменты:
   │     set_product · update_order(fields) · set_status · escalate(reason, summary)
   ├─ отправка ответа (Graph API /messages)
   └─ upsert строки воронки в Sheets
n8n ─ WF3 «Эскалация / заявка»
   └─ Telegram: карточка лида + ссылка + скриншот; статус в Sheets
n8n ─ WF4 «Сервис» (cron)
   ├─ продление токена IG (раз в ~50 дней)
   ├─ обновление кеша справочников (раз в 10 мин)
   └─ алерт: неизвестный ad_id, ошибки отправки
```

## 7. Модель данных

Одна Google-таблица, 7 листов. **Кто пишет** в лист определяет, кто его редактирует:
🧑 только человек · 🤖 только бот · 🧑🤖 общий (у каждой колонки свой владелец).

### 7.1 `Товары` 🧑 (существующий лист)
`SKU · Название · Категория · Описание · Цена · Остаток · Ссылка · Активен`
- Ключ `SKU`, уникальный и неизменный.
- Бот видит только строки с `Активен = да`. `Остаток` в MVP игнорируется.
- `Цена` хранится числом в сумах, без текста.
- `Описание` — единственный источник фактов. Чего в нём нет, бот не утверждает и передаёт вопрос менеджеру.
- `Ссылка` — пост об альбоме. Бот отправляет её, когда клиенту нужны подробности или фото.
- 15 SKU, поэтому весь каталог передаётся модели целиком (с кешированием промпта), поиск не нужен.

### 7.2 `Реклама` 🧑
| Колонка | Пример | Назначение |
|---|---|---|
| ad_id | 120210000000000 | из Ads Manager |
| Кампания | Осень_Свадебные | для аналитики |
| SKU | ALB-007 | какой товар рекламируется |
| Стартовый текст | Хочу альбом «Наша история» | уникальный, уровень 2 определения товара |
| Активна | да | |

Одна строка = одно объявление. Если SKU в рекламе несколько, ставим главный, остальные бот предложит сам.

### 7.3 `Скрипты` 🧑: этапы продажи
| Этап | Цель этапа | Что бот должен сделать/узнать | Пример ответа | Переход дальше, когда… |
|---|---|---|---|---|
| 1. Приветствие | Подтвердить интерес к товару из рекламы | Назвать товар, цену, 1–2 преимущества, ссылку на пост | … | клиент ответил по товару |
| 2. Выбор | Зафиксировать SKU и кол-во | Уточнить кол-во, предложить альтернативу | … | SKU и кол-во известны |
| 3. Оплата | Озвучить сумму и способы оплаты | Сумма, ссылки Click/Payme, напоминание про доставку | … | клиент согласен |
| 4. Данные | Собрать телефон, время, адрес, скриншот | Спрашивать недостающие поля по одному | … | все 4 поля есть |
| 5. Финал | Передать менеджеру | «Спасибо, проверяем оплату…» | … | — |

Это **инструкции и примеры** для модели, а не жёсткий сценарий. Модель держит цель этапа, но формулирует ответы сама.

### 7.4 `Возражения_FAQ` 🧑
| Тип (возражение/вопрос) | Триггер (что пишет клиент) | Ответ / позиция | Передать менеджеру? (да/нет) |
|---|---|---|---|
| возражение | дорого | … | нет |
| вопрос | можно ли скидку | … | да |

### 7.5 `Настройки` 🧑
| Ключ | Значение |
|---|---|
| bot_enabled | да *(аварийный выключатель: «нет» = бот молчит, все сообщения идут менеджеру)* |
| payment_text | текст про оплату + ссылки Click / Payme |
| delivery_text | «Доставка оплачивается отдельно курьеру по тарифам Яндекс такси» |
| order_fields | телефон, время получения, адрес, скриншот оплаты |
| tg_chat_id | группа менеджеров в Telegram |
| pause_hours | 24 — через сколько часов бот снова отвечает после последнего сообщения менеджера |

### 7.6 `Воронка` 🧑🤖 (одна строка = один клиент, ключ IGSID)
| Колонка | Владелец | Примечание |
|---|---|---|
| IGSID | 🤖 | ID клиента в Instagram |
| Ник / Имя | 🤖 | |
| Ссылка на чат | 🤖 | |
| Первый контакт / Последнее сообщение | 🤖 | дата-время |
| ad_id / Кампания | 🤖 | |
| Товар из рекламы (SKU) | 🤖 | |
| Как определён | 🤖 | ad_id / текст / спросили / неизвестно |
| Выбранный SKU / Кол-во / Сумма | 🤖 | |
| Телефон / Время получения / Адрес | 🤖 | |
| Скриншот | 🤖 | ссылка на файл |
| **Статус** | 🤖 → 🧑 | бот ведёт до «Ожидает проверки оплаты»; дальше только человек |
| Причина эскалации | 🤖 | меню / просьба / голосовое / вне скрипта / скриншот |
| Бот на паузе | 🤖 | зеркало состояния из Supabase |
| Ответственный | 🤖 | TG-ник того, кто нажал «Взял в работу» |
| Комментарий менеджера | 🧑 | бот не трогает |

**Правило записи:** бот обновляет строку только в своих колонках и никогда не откатывает статус назад. Статусы `Подтверждён`, `Доставлен`, `Потерян` ставит только человек.

### 7.7 `Лог` 🤖
Дата · IGSID · событие (эскалация, ошибка отправки, неизвестный ad_id, токен) · детали. Нужен для разбора и отладки в пилоте.

### Статусы воронки
`Новый → В диалоге → Выбрал товар → Ожидает оплаты → Ожидает проверки оплаты → Подтверждён → Доставлен`
Боковые статусы: `Нужен менеджер`, `Потерян / молчит`.

### Supabase (источник истины для бота)
`leads` (IGSID, этап, поля заказа, флаг паузы, ad_id), `messages` (история для контекста модели), `inbox` (буфер склейки).
Google Sheets служит витриной и справочниками. Поэтому ручные правки в `Воронке` бот не читает, кроме тех, что идут через кнопки Telegram (см. 7.8).

### 7.8 Уведомление в Telegram
```
🟢 Новая заявка | 🟠 Нужен менеджер (причина)
👤 @nick (Имя) — ссылка на чат
📣 Кампания: Осень_Свадебные · SKU ALB-007
🛒 «Наша история» × 1 = 350 000 сум
📞 +998… · 🕒 завтра после 18:00 · 📍 адрес
📝 Суть: 2–3 строки от модели
[скриншот оплаты вложением]
Кнопки: [Взял в работу] [Вернуть бота]
```
Уведомления уходят в **группу** менеджеров. «Взял в работу» записывает в `Воронку` ник нажавшего и меняет подпись сообщения в группе («🙋 @manager взял»), чтобы двое не ответили одному клиенту. «Вернуть бота» снимает паузу сразу. Иначе пауза снимается автоматически через 24 ч после последнего сообщения менеджера.

## 8. План

| Фаза | Содержание | Срок | Кто |
|---|---|---|---|
| **0. Проверка жизнеспособности** | Meta app (Standard Access) → вебхук в n8n → эхо-ответ постороннему аккаунту; клик по действующей рекламе: приходит ли `ad_id`; повторный клик из существующего диалога; постоянное меню | 1–2 дня | Шухрат (доступ к Meta) + инструкция от меня |
| **Gate** | Если `ad_id` не приходит, уникальные стартовые тексты становятся обязательными. Если без App Review писать нельзя, пересматриваем вариант с ManyChat | — | решение Шухрата |
| 1. Каркас | WF1 + WF3 (приём, склейка, пауза, эскалация в TG), листы таблицы | 2–3 дня | |
| 2. Мозг | WF2: системный промпт, инструменты, сбор заявки, upsert воронки | 3–4 дня | |
| 3. Тесты | 30+ тестовых диалогов (ru/uz, возражения, голосовые, скриншот, вмешательство менеджера) | 2 дня | |
| 4. Переезд | VPS, перенос сценариев, повторный ввод доступов, смена адреса вебхука | 0,5 дня | |
| 5. Пилот | Живой трафик, ежедневный разбор 10 диалогов первую неделю | 2 недели | |

Демо n8n на 14 дней покрывает фазы 0–3, поэтому фаза 4 должна пройти до его окончания.

## 9. Риски

| Риск | Вероятность | Митигация |
|---|---|---|
| Instagram не отдаёт `ad_id` в `referral` | средняя | уникальный стартовый текст в каждом объявлении |
| Для сообщений посторонним нужен App Review | низкая (по документации) | проверяется в Фазе 0, план Б: ManyChat |
| Фейковые скриншоты оплаты | высокая | бот не подтверждает оплату, проверяет менеджер |
| Слабое качество ответов на узбекском | средняя | тесты; при неудаче узбекский → менеджеру |
| Забыли добавить новый ad_id в справочник | высокая | алерт в TG + запасные уровни определения |
| Демо n8n закончится до переезда | средняя | переезд — жёсткий пункт до запуска рекламы |
| Токен IG истёк | низкая | cron-продление + алерт об ошибке |

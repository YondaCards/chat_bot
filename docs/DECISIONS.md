# Журнал решений — ИИ-бот Yonda в Instagram Direct

Хронология решений и их обоснований из сессии проектирования. Новые решения дописываются внизу.

## 2026-10-08

| # | Решение | Почему / альтернативы |
|---|---|---|
| D1 | Стек: **n8n + прямой Instagram Graph API** (без ManyChat) | ManyChat ≥ $17/мес не укладывается в бюджет MVP. По документации Meta, для своего бизнес-аккаунта хватает Standard Access, App Review не нужен. Проверяется в Фазе 0, план Б — ManyChat |
| D2 | Бюджет: VPS ≈ $5–10 + Claude Haiku 5.5 ≈ $3–6/мес | Haiku 5.5: $0.10 / $0.50 за 1M токенов. Sonnet 5.5 обошёлся бы в ~$60–100/мес при 10–20 лидах в день |
| D3 | Остатки в MVP не используются | Решение заказчика. Устаревший остаток хуже, чем никакого. Вместо них фильтр `Активен` |
| D4 | Хранилища: Google Sheets (витрина + справочники) + Supabase free (состояние, история, буфер) | Sheets как единственная БД ломается на одновременной записи. Supabase одинаково работает с демо n8n и с VPS, переносить данные не нужно |
| D5 | Разработка на демо n8n (14 дней), прод на VPS. **Реклама на демо не запускается** | Демо закончится, и бот замолчит посреди диалогов |
| D6 | Товар из рекламы определяется по 3 уровням: `referral.ad_id` → уникальный стартовый текст объявления → уточняющий вопрос | Для Instagram передача `ad_id` подтверждена только косвенно (официальный пример есть для Messenger). Проверяется в Фазе 0 |
| D7 | Справочник рекламы (ad_id → кампания → SKU) ведётся вручную + алерт о неизвестном ad_id | Marketing API для MVP избыточен |
| D8 | Голосовые сообщения → сразу менеджеру | Расшифровка вне MVP |
| D9 | Бот не подтверждает оплату. После скриншота статус «Ожидает проверки оплаты», скриншот уходит в TG | Фейковые скриншоты, проверить оплату может только человек |
| D10 | «Позвать менеджера»: постоянное меню + распознавание просьбы текстом | Persistent menu поддерживается в Instagram API with Instagram Login. Quick replies не проверены и исчезают после нажатия |
| D11 | Пауза бота: автоматически по echo-сообщению менеджера; снимается кнопкой «Вернуть бота» или через **24 ч** | 24 ч совпадает с окном ответа Meta |
| D12 | Уведомления в **группу** TG, кнопка «Взял в работу» фиксирует ответственного | Чтобы двое менеджеров не отвечали одному клиенту |
| D13 | Языки: русский основной, узбекский — отвечать на языке клиента | Качество на узбекском проверяется в тестах; при плохом результате узбекский → менеджеру |
| D14 | Альбомы готовые (не персонализированные), 15 SKU, весь каталог передаётся в контекст модели | Поиск по каталогу не нужен |
| D15 | `Ссылка` в `Товары` — пост об альбоме, бот отправляет её как подробности/фото | Отправка поста карточкой проверяется в Фазе 0 |
| D16 | Таблица: 7 листов (Товары, Реклама, Скрипты, Возражения_FAQ, Настройки, Воронка, Лог), у каждой колонки один владелец | Бот не откатывает статус и не трогает колонки менеджера |
| D17 | Ручной базы конверсии нет, база = первые 2 недели пилота | — |
| D18 | Доставка: только «оплачивается курьеру по тарифам Яндекс такси», без оценки суммы | Решение заказчика |
| D19 | Все артефакты хранятся в репозитории `YondaCards/chat_bot` (основная ветка `main`) | Решение заказчика. Отдельный репозиторий под проект, а не `camera` |
| D20 | **PRD v0.3 утверждён**, переход к Фазе 0 | Sign-off заказчика |
| D21 | Шаблон таблицы: 7 рабочих листов + лист «Инструкция»; цвет заголовка = владелец колонки | Чтобы правила владения колонками были видны прямо в таблице |
| D22 | Сценарий Фазы 0 отвечает **только** IGSID из списка `ALLOWED_SENDERS`, остальных лишь логирует в TG | Реклама крутится, и реальные клиенты не должны получать тестовое эхо |

## Открытые темы
- Ссылка на чат в TG (`ig.me/m/<username>` или Inbox Business Suite): Фаза 0.
- Tone of voice, скрипты, правила скидок и торга: отдельная сессия.
